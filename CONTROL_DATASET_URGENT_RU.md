# Последний час: контрольный набор Freedom Broker

Организаторы предоставили два раздельных набора:

| Набор | ID | Что делать |
|---|---|---|
| **FBroker** | 10 чатов, `p2-*` | Оценить по основному чек-листу, экспортировать **только** в `results/prod/results.json` |
| **Swap** | 3 чата, `p3-*` | **Только сохранить отдельно**, НЕ оценивать сейчас, НЕ добавлять в PROD |

## Действия (Windows, в работающей v1.2 / v1.2.1)

1. Сделайте копию `cqa.sqlite3` и `.env`. Не публикуйте их.
2. Убедитесь, что в вашем **локальном** `.env` есть рабочий `CQA_LLM_API_KEY`, `CQA_LLM_BASE_URL`, `CQA_LLM_MODEL`; без них Qwen не оценит новые чаты. **Не загружайте `.env` в GitHub.**
3. Запустите `run_windows.bat`. Откройте **Диалоги** → **Загрузить JSON**, выберите скачанный `FBroker_10_Import.json`. Должно появиться **FBroker (10)**.
4. `SWAP_3_Keep_Only.json` храните отдельно как резервную копию и не импортируйте, если в этом нет необходимости. Она не участвует в текущей сдаче.
5. В фильтре **Набор данных** выберите **FBroker**. И только затем нажмите **Оценить новые**. Программа должна предложить **10**, а не 65, 75 или 78. Если число другое — отмените и проверьте фильтр. Запросы к Qwen расходуют квоту.
6. Дождитесь полного завершения пакетной оценки и проверьте число успешно оценённых чатов. При ошибках оцените конкретные ID повторно; не запускайте повторный batch со всеми наборами.
7. **Сдача JSON** → настоящее **название команды** → **FBroker** → **тот же чек-лист**, что использовался для оценки → **Сформировать PROD JSON (10)**. Проверьте: **total 10 / OK 10 / ERROR 0**.
8. Скачайте JSON или возьмите локально `results/prod/results.json`. Обязательно положите его в **корневой `results/prod/results.json` репозитория**.
9. Дополнительная строгая проверка (без вызовов LLM), из корня проекта:
   ```powershell
   py scripts/last_hour_preflight.py --dataset FBroker_10_Import.json --results results/prod/results.json
   ```
   Вы должны увидеть `READY FOR PROD PUSH: exactly 10 evaluated FBroker chats.`
10. Отправьте через Git и ПРОВЕРЬТЕ GitHub:
    ```powershell
    git add results/prod/results.json
    git commit -m "Submit FBroker control results"
    git push origin main
    ```
11. Убедитесь, что в открытом GitHub-репозитории есть и `results/dev/results.json`, и `results/prod/results.json`, доступны без авторизации. Если DEV не полностью оценён, повторяющиеся `status:error` остаются проблемой полноты, но нельзя выдумывать результаты.

## Важное

`FBroker_10_Import.json` — исходные чаты, это **НЕ** файл итоговых оценок. **Нельзя** переименовать его в `results/prod/results.json`. Итоговый файл должен содержать `schema_version`, `team_name`, `model`, и `results` с восемью критериями на каждый успешно оценённый чат. Имена полей, `evidence_turns` (нумерация с 1), N/A, веса, отдельный `critical_flag` должны соответствовать приложению организаторов.

Если в интерфейсе у набора написано `Swap` или `DEV`, то для PROD выбран НЕ тот набор. Указанное организаторами API для скачивания контрольных чатов — это не обязательно API ключ для модели. Для Qwen используйте свой рабочий ключ Groq.
