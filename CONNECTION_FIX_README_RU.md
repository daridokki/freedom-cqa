# Freedom CQA — исправление подключения Gemini (Windows)

## Что изменилось

- Переключён AI-адаптер на **нативный Gemini REST API** (`models/{model}:generateContent`).
- Системная инструкция передаётся как `systemInstruction`, транскрипт — как `contents`.
- При `CQA_LLM_JSON_MODE=1` используется нативный `generationConfig.responseMimeType=application/json` вместо OpenAI `response_format`.
- Остались прежними FastAPI, веб-интерфейс, SQLite, чек-лист и математический расчёт.
- Изменён `check_gemini.py`: отдельно проверяются авторизация GET, **авторизованный POST с намеренно неправильным телом**, потом настоящая генерация. Это помогает отличить сетевую проблему от торможения модели.
- Ошибки провайдера теперь содержат текст Google (ключ из него удаляется); сетевые тайм-ауты явно различаются.

## Как установить, не потеряв данные и ключ

1. **Закрой окно с сервером** (`Ctrl+C`).
2. Сделай резервные копии `C:\Freedom_CQA_Gemini\.env` и `C:\Freedom_CQA_Gemini\cqa.sqlite3`, если база уже содержит оценки.
3. Для малого патча: замени в исходной папке только `llm.py` и `check_gemini.py`. Для полного архива: распакуй программу в отдельную папку и перенеси в неё свои `.env` и `cqa.sqlite3` (не наоборот).
4. В **существующий** `.env` добавь/исправь строки (сам ключ НЕ отправляй в чат):

   ```ini
   CQA_LLM_PROVIDER=gemini_native
   CQA_LLM_MODEL=gemini-3.8-flash
   CQA_LLM_JSON_MODE=1
   CQA_LLM_TIMEOUT=90
   CQA_LLM_HTTP_RETRIES=1
   CQA_BATCH_WORKERS=1
   CQA_BATCH_DELAY_SEC=8
   ```

   Сохрани свою строку `CQA_LLM_API_KEY=...` без изменений. `CQA_LLM_BASE_URL` с native-адаптером не используется.

5. Запусти `check_gemini_windows.bat` (в проекте должно быть установлено виртуальное окружение `.venv` через `run_windows.bat`).

## Как понять три этапа

- **STEP 1:** `GET HTTP: 200` — ключ действует и модель доступна через metadata API.
- **STEP 2:** `POST probe HTTP: 400` — это **успех диагностики**: намеренно невалидный запрос дошёл до Google **с твоим ключом**. Ничего генерироваться не должно.
- **STEP 3:** `Generation HTTP: 200`, `Model reply: 'OK'` — настоящая генерация работает.

Если STEP 2 даёт `NETWORK ERROR`, это проблема прохождения авторизованного POST или конфигурации HTTPS/прокси, ещё до генерации. Если STEP 2 даёт 400, а STEP 3 — `ReadTimeout`, проблема возникает именно при инференсе; это ещё **не доказывает баг в нашем коде**. Проверь модель через API (ответ в AI Studio — отдельная проверка), лимиты, другую сеть/прокси; **не запускай все 65 диалогов**, пока STEP 3 не пройдёт.

После STEP 3 запускай `run_windows.bat`, открой `http://127.0.0.1:8000`, импортируй DEV JSON, оцени **один** `p1-ru-022`, проверь обоснование и грубое нарушение №8. Для проверки логики программы (без реального API) запусти `run_tests_windows.bat`.

## Безопасность и проверенные ограничения

- В патче нет ключа Google и нет файла `.env`.
- Реальный Gemini-запрос здесь не проверялся: ключ доступен только на твоём компьютере. Автоматические тесты мокируют сеть, и их успех не гарантирует доступность API из твоей сети.
- Бесплатный Gemini-тариф может иметь ограничения обработки данных. Не отправляй реальные клиентские записи без разрешения.
