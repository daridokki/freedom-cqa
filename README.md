# FREEDOM CQA — Conversation Quality Analytics

Рабочий прототип системы контроля качества диалогов Freedom Broker для Data Challenge / CQA Hackathon. Реализован под **HTML / CSS / JavaScript**, с возможностью дальнейшего переноса UI в HTML-компонент Dynamics 365. Backend: Python / FastAPI. Хранение: SQLite. Для демонстрации нет регистрации и входа, как указано в ТЗ.

**Важно:** Поставщик AI-модели не включён в исходный код и оплачиваемый API не активирован. Реальная AI-оценка начинает работать **только после указания своего ключа**. Без ключа доступны импорт, UI, чек-листы, ручные оценки через API и отдельный **явно маркированный учебный пример**. Пример не следует выдавать за AI-результат. Перед отправкой реальных клиентских данных внешней модели проверьте, что это допускается правилами организаторов и вашей политики конфиденциальности.

## Быстрый запуск

### Windows

1. Установить **Python 3.11+**.
2. Распаковать весь архив в отдельную папку.
3. Дважды щёлкнуть `run_windows.bat` или выполнить вручную:

   ```powershell
   py -3 -m venv .venv
   .venv\Scripts\python.exe -m pip install -r requirements.txt
   Copy-Item .env.example .env
   .venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000
   ```

4. Открыть **http://127.0.0.1:8000**.

### macOS / Linux

```bash
chmod +x run_unix.sh
./run_unix.sh
```

Либо запустить вручную `python3 -m venv .venv`, `pip install -r requirements.txt`, `uvicorn app:app --host 127.0.0.1 --port 8000`.

### Docker (необязательно)

```bash
cp .env.example .env  # Windows: copy .env.example .env
# Укажите модель и API key, если нужен реальный AI-анализ.
docker compose up --build
```

Данные сохраняются в Docker volume `cqa-data`. База данных и `.env` не должны попадать в публичный репозиторий.

## Как подключить AI

В файле `.env` (создаётся копированием `.env.example`) заполните Gemini API key:

```ini
CQA_LLM_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai/
CQA_LLM_API_KEY=ВСТАВЬТЕ_СВОЙ_GEMINI_КЛЮЧ
CQA_LLM_MODEL=gemini-2.5-flash
CQA_LLM_JSON_MODE=1
CQA_BATCH_WORKERS=1
CQA_BATCH_DELAY_SEC=8
CQA_INPUT_USD_PER_1M=0
CQA_OUTPUT_USD_PER_1M=0
```

**Ключ может создаваться бесплатно, а доступность выбранной модели, запросов и лимитов зависит от AI Studio.** Проверьте соединение через `check_gemini_windows.bat`; `/api/health` подтверждает только настройку переменных. Подробный сценарий смотрите в `GEMINI_WINDOWS_GUIDE.md`.

Система вызывает совместимый интерфейс `POST /chat/completions`. Выберите конкретную мультиязычную модель по тарифам и требованиям к качеству. Некоторые поставщики поддерживают JSON mode (`CQA_LLM_JSON_MODE=1`), другие — нет. Для модели, которая не принимает `temperature:0`, адаптируйте одно поле в `llm.py`. **Ключи хранятся только на сервере, не внутри JavaScript.** После редактирования `.env` перезапустите процесс.

При положительных ценах в `CQA_INPUT_USD_PER_1M` и `CQA_OUTPUT_USD_PER_1M` интерфейс показывает ориентировочную стоимость оценки на основе **суммы всех токенов во всех попытках**, в том числе после невалидного первого ответа. Если цены равны 0, цена не показывается, чтобы не создавать впечатление бесплатного API.

Пробный вызов (перед массовым запуском): **Диалоги → Оценить**. После 2–3 успешных единичных оценок используйте **Оценить новые** — это запускает серверную очередь из конфигурируемого числа запросов (для Gemini по умолчанию — один запрос и пауза 8 секунд) с сохранением прогресса в SQLite. После перезапуска незавершённая задача помечается как `interrupted`, её можно запустить снова; уже оценённые диалоги пропускаются.

## Как импортировать диалоги

**Реальные данные организаторов:** откройте страницу 3 файла `CQA_Hackathon_Student_Guide_v3.pdf`; у кнопки **«Открыть GET для DEV»** скопируйте полную ссылку. В поле «Импорт GET» вставьте её целиком, затем нажмите кнопку импорта. Ссылка содержит служебную подпись: **не добавляйте её в Git, README, исходники или скриншоты**. Backend загружает данные, сохраняя `conversation_id`, `channel`, `language`, `timestamp`, `speaker`, `text`, `audio_url`, `dataset_group_id`. При ошибке CORS используется серверное обращение к GET. Для контрольного набора организаторы предоставят другое значение `group_id`.

**Локальный файл DEV:** положите `Freedom_CQA_DEV_65.json` в папку `data/` (она в `.gitignore`) и загрузите его кнопкой «Загрузить JSON». Файл не хранится в репозитории: в нём реальные звонки и подписанные ссылки на записи.

**Без реальных данных:** в папке `sample_data/` есть `synthetic_multilingual.json` — **4 явно синтетических диалога RU/KZ/EN, включая голосовой транскрипт**. Нажмите «Загрузить JSON» и выберите файл. Это только тест интерфейса; качества реальных данных по нему не измерить.

Поддерживаемые роли: `operator`, `client`, `bot`, `system`. Бот и системные сообщения используются как контекст, но не оцениваются как ответы оператора. Отметки времени чатов сохраняются в `MM:SS`, звонков — в исходном ISO 8601 с часовым поясом. Если `audio_url` непустой, доступен встроенный плеер и внешний переход. **Оценка интонации или дикции не выполняется по тексту:** аудиоаналитика не включена, так как исходный чек-лист её не требует.

## Работа в интерфейсе

1. **Обзор.** Количество диалогов и оценок, средние оценки по языкам, выполнение критериев, количество открытых апелляций. Агрегируются финальные оценки с учётом решений проверяющих.
2. **Диалоги.** Импорт DEV/контроля, фильтры по языку/каналу/группе, индивидуальная и пакетная AI-оценка. Данные не переписываются, если по тому же `conversation_id` прислан другой текст: конфликт возвращает 409 для сохранения доказательств.
3. **Результаты.** Итог 0–100, секции, флаг грубых нарушений, ответ, нормализованный вес, объяснение, кликабельные ссылки на оригинальные реплики. Оригинальная и финальная оценки видны после пересмотра. Экспорт агрегированных результатов в CSV и отдельного результата в JSON.
4. **Апелляции.** Клиент проверки подаёт апелляцию по конкретному критерию, проверяющий подтверждает или меняет ответ с обязательным объяснением, при необходимости указывает новые номера реплик-доказательств. Оригинальная оценка остаётся неизменной.
5. **Чек-лист.** Можно изменить название, секцию, вес, правило, шкалу, N/A, тип (`yes/no`, шкала, отдельный флаг); добавить новый критерий или удалить старый. Каждое сохранение создаёт **новую версию**. Старая версия остаётся привязанной к прошлым оценкам. Для нового критерия **не требуется обновлять Python-код**.

## Правила баллов — как в PDF Freedom Broker

Начальная конфигурация — **8 критериев**:

| ID | Критерий | Тип | Вес |
| --- | --- | --- | ---: |
| 01 | Установление контакта | Да/Нет | 10 |
| 02 | Выявление потребности | Да/Нет/N/A | 15 |
| 03 | Идентификация | Да/Нет/N/A | 20 |
| 04 | Корректная и полная консультация | 0,5,10,15,20 / N/A | 20 |
| 05 | Эмпатия и клиентоориентированность | Да/Нет | 15 |
| 06 | Управление диалогом, скорость и грамотность | 0,4,7,10 | 15 |
| 07 | Завершение | Да/Нет/N/A | 5 |
| 08 | Грубые ошибки | Да/Нет (отдельный флаг) | 0 |

Для `yes` коэффициент 1, `no` — 0, для шкалы коэффициент `level/max(levels)`. `na` **исключает** критерий из числителя и знаменателя. Результат (округление half-up до 2 знаков):

```text
score = 100 × SUM(weight_i × fraction_i for applicable criteria)
            / SUM(weight_i for applicable criteria)
```

Веса могут изменяться: после N/A сумма **пропорционально нормализуется к 100**. Если ни один взвешенный критерий неприменим, итог — `null` (не рассчитывается). Критерий грубой ошибки **не обнуляет** итог: отдельное значение `gross_error=true`.

Для N/A используются только условия исходного PDF (например, при общем вопросе о тарифах **не нужна** идентификация; если проверка требовалась, но не подтверждена, ставится **Нет**). Порог первой реакции в 3 минуты, теги и вложения в начальном задании **не оцениваются**.

## API

OpenAPI: **http://127.0.0.1:8000/docs**. Основные эндпоинты:

| Метод | Маршрут | Результат |
| --- | --- | --- |
| GET | `/api/health` | Состояние сервиса |
| GET | `/api/state` | Диалоги, версии, оценки, задачи |
| POST | `/api/import/url` | Импорт от организаторов через сервер |
| POST | `/api/import/json` | Импорт локального JSON |
| GET | `/api/conversations/{id}` | Оригинальный транскрипт |
| POST | `/api/evaluations` | Реальная AI-оценка |
| POST | `/api/evaluations/manual` | **Явная** ручная оценка, не AI |
| GET | `/api/evaluations/{id}` | Оригинал, финал, доказательства, апелляции |
| POST | `/api/checklists` | Сохранить новую версию |
| POST | `/api/appeals` | Подать возражение |
| POST | `/api/appeals/{id}/decision` | Подтвердить или изменить оценку |
| GET | `/api/review-queue` | Открытые апелляции |
| GET | `/api/analytics` | Агрегация по языкам/критериям |
| GET | `/api/export/results.csv` | Экспорт CSV (с защитой от формульных инъекций) |
| GET | `/api/evaluations/{id}/export.json` | Полный JSON-отчёт |
| POST | `/api/jobs/batch` | Запуск пакетной оценки |
| GET | `/api/jobs/{id}` | Прогресс и ошибки |
| POST | `/api/jobs/{id}/cancel` | Запрос остановки после текущих вызовов |

```bash
python -m unittest discover -s tests -v
```

Включены сквозные тесты импорта и дубликатов, N/A, шкал и грубых нарушений, редактора чек-листа, ручной оценки, апелляции с изменением результата, экспорта, фоновой пакетной очереди, запрета недопустимых реплик и **мокированного AI API**. Настоящий платный LLM не вызывается в тестах.

## Предлагаемый сценарий защиты (5 минут)

- **0:00–1:00:** Обзор; импорт DEV; RU/KZ/EN, выбранный разговор и настройки.
- **1:00–3:00:** Оценка; N/A; кликабельное обоснование; нормализованный балл; отдельный флаг грубого нарушения.
- **3:00–4:00:** Подача апелляции → решение проверяющего → изменившийся итог, сохранённый оригинал.
- **4:00–5:00:** Чек-лист → изменение/новый критерий → сохранение v2 → переоценка выбранного диалога.

**Перед стоп-кодом:** импорт контрольного набора, запуск оценки; публичный Git-репозиторий **без** `.env`, SQLite и исходных клиентских разговоров; README с запуском. После стоп-кода не меняйте исходники — интерфейс и переоценка остаются доступны.

## Что не подтверждено тестированием

- **Точность на 65 настоящих диалогах и контрольном наборе**: настоящие записи не включены в архив, ключ AI не предоставлен. Для оценки качества рекомендуется вручную разметить контрольные диалоги (включая KZ и сложные N/A), затем сравнить с моделью и выбрать лучший провайдер.
- **Финансовая правильность консультации** без актуальной одобренной базы тарифов и нормативных документов не может быть гарантирована LLM. Требуется экспертная проверка спорных консультаций и серьёзных нарушений.
- **Анализ акустических признаков** речи (дикция/интонация) не реализован. Транскрипт и запись доступны в UI.
- **Продукционная безопасность:** учебное решение по заданию без авторизации; не выкладывайте в публичный интернет с реальными данными без access control, шифрования/retention-политик и соответствующей проверки.
